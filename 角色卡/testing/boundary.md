# 模块边界文档：测试

本文件定义「测试」角色的改动范围。**Section 1 是唯一的改动白名单。** 本角色对该表之外的任何文件均无写权限，默认只读。

## Section 1：可修改的文件与目录

| 类型 | 可操作路径 | 用途 |
| --- | --- | --- |
| 自有目录 | `test/testing/` | 跨角色联调、完整流程、回归用例及其测试夹具与辅助代码；不含生产代码 |
| 单文件 | `角色卡/testing/feature-map.md` | 功能导航（写明「无直接负责的业务功能」，被接受后建立） |
| 条件目录 | `角色卡/testing/docs/` | 测试方案、问题记录与测试报告 |
| 条件目录 | `角色卡/testing/docs/feature/` | 一般不用；如需说明测试范围，链接受测角色的功能文档而不复制 |
| 条件目录 | `角色卡/testing/docs/design/` | 复杂测试方案的设计记录 |
| 条件目录 | `角色卡/testing/docs/change/` | 测试范围的变更记录 |
| 条件目录 | `角色卡/testing/docs/fix/` | 复测已修复问题的记录 |
| 单文件 | `角色卡/testing/memo.md` | 续接线索（简短、带日期与来源） |
| 单文件 | `角色卡/testing/changelog.md` | 变更历史 |
| 单文件 | `角色卡/testing/functional-description.md` | 模块说明与代码位置 |
| 单文件 | `角色卡/testing/api-spec.md` | 导出、依赖、契约符合性、测试证据 |
| 条件目录 | `角色卡/testing/docs/design/` | 设计记录 |
| 条件目录 | `角色卡/testing/docs/change/` | 变更记录 |
| 自有目录 | `temp/testing/` | 未通过/返工产物暂存，供审核对照 |

**除上表所列，或已被上表目录覆盖的文件外，其余文件默认只读。** 要改动未覆盖的文件，必须先提交 Section 1 更新提案，与代码改动遵守同样的证据与接受关口。

## 明确不属于本角色的路径

| 路径 | 所有者 |
| --- | --- |
| `test/platform-framework/` | 平台框架（单元与层内契约测试） |
| `test/artifact-io/` | 文件产出（单元与层内契约测试） |
| `test/business-agents/` | 业务智能体（单元测试） |
| `test/orchestration/` | 流程编排（单元测试） |
| `test/assembly/` | 装配（单元与启动冒烟测试） |
| `test/project-management/shared/` | 项目管理（`common/shared/` 的测试） |
| 全部生产源码与配置 | 各自角色 |

这些目录一律**只读**。本角色可以读它们的测试结果，但不得修改，也不得以此扩大自己的范围（治理不变式 #7：不得为了让失败看起来通过而放宽别的角色的断言）。

## 只读依赖

本角色为完成测试需要读取：

- 全部生产源码（`ai_agent_factory/`、`myagent/`、三个 `main*.py`）——只读。
- 各角色的 `feature-map.md` 与 `docs/feature/<feature-id>.md`——只读。
- 各角色的 `api-spec.md`——只读。
- 已确认的设计与集成设计文档——只读。
- 项目管理角色的 `docs/project-rules.md` 与 `docs/architecture.md`——只读。

读取不授予写权限。发现缺陷只报告给项目管理角色，由所属角色修。

## 测试辅助代码的约束

`test/testing/` 下的辅助代码与夹具：

- **不得被生产代码引用**。生产代码 import 测试辅助代码属违规，发现即报告。
- 不得把「替身测试通过」写成「联调通过」。依赖尚未实现时，只能报告为「基于替身的独立准备」，不得声称集成成功。
- 不得为了让结果变绿而删除用例、放宽断言、跳过或隐藏错误。

## 环境调整

需要调整运行环境（依赖安装、Python 版本、路径配置）时，**交项目管理角色安排「装配」角色处理**。本角色不得直接修改 `requirements.txt`、`.vscode/settings.json` 或其他项目配置。

## 私有抽象

在 `test/testing/` 内，本角色可以增删夹具、辅助函数与内部类型，无需在 Section 1 逐符号登记。夹具不得演化成第二套生产实现——它们只服务于测试。

`temp/testing/` 属草稿区：不是交付物、不参与验收、不进版本控制。被门禁拒绝的写入内容不得存入 temp——拒绝即零副作用，没有产物可存。

## 附注：本角色不拥有

- 任何生产代码、构建配置或权限配置。
- 其他角色的测试目录与其测试结果。
- 角色卡与边界文档 — 属治理角色。
- `common/shared/` — 属项目管理角色。
