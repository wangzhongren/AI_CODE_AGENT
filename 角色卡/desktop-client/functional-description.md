# 模块说明：桌面客户端（`desktop/`）

## 这是什么

桌面端把「流程编排 → 业务智能体」这条已有的终端管线包进一个窗口。用户第一次
「看见」这套系统就是在这里：写下一句话需求、点发送、看文字一行行长出来。

它**不生成任何内容**，也不决定下一步调度谁——那些属于编排层与业务智能体。
桌面端只做三件事：把用户的输入交出去、把编排层吐的事件画出来、窗口关闭时干净收场。

## 用户能做什么（S4 范围）

1. 启动：项目根目录执行 `.venv\Scripts\python.exe -m desktop`，出现一个窗口。
2. 输入：窗口底部输入框里写需求，按回车或点「发送」。
3. 观看：文字在输出区里逐字出现；一轮回复结束会另起一段；出错时红色加粗显示。
4. 关闭：直接关窗口。程序会停止接收新任务、不再往界面写内容、退出。

启动顺序：先把 `sys.stdout` / `sys.stderr` 兜住（无控制台模式下可能是 `None`），
再建窗口。这样管线里的 `print` 不会把程序炸掉。

## 界面长什么样（2026-10-17 视觉改造后）

窗口自上而下分三段：

1. **顶栏**：左边标题「代码生成助手」，右边状态胶囊，底部一条 1px 分隔线。
   胶囊由 8px 圆点和文字组成：就绪是浅灰底 + 灰点，运行中是浅蓝底 + 蓝点，
   出错时是浅红底 + 红点（任务结束后恢复就绪）。
2. **输出卡片**：白底、12px 圆角、1px 浅边框、18px 内边距，占满顶栏与输入行之间的空间；
   文字 14px，段落之间留 6px 间距，滚动条宽 10px。
3. **输入行**：左侧输入框（高 42px、10px 圆角，聚焦时边框变主色），右侧发送按钮
   （高 42px、10px 圆角、主色底白字、最小宽 88px，含悬停 / 按下 / 禁用三态）。
   下方一行 12px 辅助提示说明「运行中可关闭窗口中断任务」。

配色：窗口背景 `#F4F6F8`、卡片 `#FFFFFF`、边框 `#E3E8EF`、主文字 `#1D2430`、
次要文字 `#6B7684`、主色 `#2F6FEB`（悬停 `#2559C7`、按下 `#1E47A8`、禁用 `#C7D6F5`）。
字体回退链：`Microsoft YaHei UI` → `PingFang SC` → `Segoe UI` → `sans-serif`。
样式全部在 `desktop/window.py` 的模块级 `WINDOW_STYLESHEET` 里，只挂在窗口上，
不影响测试共用的全局应用实例。

## 代码在哪

| 你想看… | 去这个文件 |
| --- | --- |
| 启动、关闭、句柄 | `desktop/app.py` |
| 窗口长什么样、文字怎么画 | `desktop/window.py`（含视觉常量与 `WINDOW_STYLESHEET`） |
| 长任务怎么挪出界面线程 | `desktop/worker.py` |
| 事件怎么从工作线程回到界面 | `desktop/output_listener.py` + `desktop/bridge.py` |
| 无控制台模式的 print 兜底 | `desktop/stdio_fallback.py` |
| `python -m desktop` 入口 | `desktop/__main__.py` |

功能级说明见 `docs/feature/desktop-shell.md`；导出与契约符合性见 `api-spec.md`。

## 三条设计底线

1. **界面线程只画图。** 管线的每次提交跑在工作线程里；C1 的回调也在工作线程，
   它只做 `signal.emit(...)`，Qt 自动把信号排队回界面线程。界面不会白屏假死。
2. **失败要看得见。** 管线抛出的异常如果没走 C1 的 `error` 事件，工作线程会补报一次；
   两者都走到同一条红色错误样式，用户不会遇到「点了没反应」。
3. **不穿透下层。** 桌面端只调用注入对象的公开方法（`set_output_listener` + 提交方法），
   不读私有字段、不 import 具体智能体类、不构造 LLM。

## 当前限制（说清楚，别猜）

1. `python -m desktop` 现在还没有接真实编排器：能开窗、能输入、能关，提交时会显示
   「桌面端还没接到编排层」。真实接线属装配步骤 S5。
2. 只收到「被注入的那一个对象」的事件。编排器派发出的子智能体是独立实例，它们的
   token 目前收不到——这是契约 C1 的实例级订阅缺口，需 C1 v2 提供下发入口。
3. 关闭时无法强杀正在跑的 LLM 请求；保证的是「不再往界面写、不接受新任务、不阻塞进程退出」。
4. 项目状态面板（契约 C2）还没做，留给下一步。
