## 1. 目标与非目标

目标：`python -m desktop` 启动一个窗口，输入框 + 发送按钮 + 输出区；提交后在**工作线程**里跑注入的编排器；C1 事件流实时渲染；关闭窗口能中断任务、回收线程、可重复关闭。

非目标（本步不做）：状态面板渲染（C2，下一步）、PyInstaller 打包、界面美化、真实 LLM 与环境变量读取（S5）。

## 2. 分层与线程模型

- 界面层只依赖注入的编排器对象：`set_output_listener(listener)` 一个方法 + 一个「提交需求」的公开方法。**不 import `myagent/` 任何模块、不 import Provider**。
- 唯一允许的下层 import 是 C1 的契约类型 `AgentOutputListener` / `AgentOutputError`（`isinstance` 校验要求必须继承它）——这是消费 C1 契约，不是依赖业务智能体。
- 线程：Qt 主线程只做渲染；提交动作创建 `threading.Thread` 跑编排器。C1 回调在**工作线程**触发，回调里只做 `signal.emit(...)`；Qt 自动排队到界面线程。
- 为了让「事件→界面」这一层**在没装 Qt 时也能测**，把 Qt 与 Qt 无关的部分切开：
  - `desktop/output_listener.py`（Qt 无关）：`AgentOutputListener` 子类，把事件转成对回调（token / 段落完成 / 错误）的调用，另记录线程 id 供测试断言。
  - `desktop/bridge.py`（Qt）：`QObject` 持三个 `Signal`，作为上面那个 listener 的接收端，实现跨线程投递。

## 3. 公开入口（C3）

```python
desktop.run(orchestrator, *, submit_method="...") -> DesktopHandle   # 语义等价 desktop.app.run(...)
DesktopHandle.shutdown()        # 中断在跑的管线、回收工作线程、可重复调用
```

- `import desktop` 不得触发 Qt 导入、不得创建 `QApplication`：Qt 在 `desktop/app.py` 的 `_load_qt()` 内懒加载。这样 `python -m desktop` 以外的地方（S5 装配、测试）import 包是零副作用。
- 句柄只暴露 `shutdown()` / `wait_closed()`，**不返回编排器、不返回 Qt 对象**，违反 C3 第 3 条。
- 启动失败（缺 PySide6、注入对象缺方法）：抛可读 `DesktopStartupError`，并把已创建的 `QApplication` / 线程清理干净。

## 4. `--noconsole` / pythonw 的 stdout 兜底

契约 C1 选择「事件与 print 并存」，整条管线靠 `print` 输出；`pythonw` 下 `sys.stdout is None`，`print` 直接抛 `AttributeError`。

做法（`desktop/stdio_fallback.py`）：启动前检查 `sys.stdout` / `sys.stderr`，为 `None` 时替换为可写的日志文件（`%TEMP%/codeagent-desktop/desktop-<date>.log`，写失败则退回 `io.StringIO`）；返回原始值以便测试还原。必须在**创建窗口之前**执行。

## 5. 改动清单

必做（M）：

- M1 `desktop/__init__.py`、`desktop/app.py`：C3 启动操作 + 关闭句柄 + 懒加载 Qt。
- M2 `desktop/window.py`：标题、输出区（只读）、输入框、发送按钮、错误醒目样式。
- M3 `desktop/worker.py`：工作线程跑管线；`shutdown()` 置取消标志、等线程退出、超时告警。
- M4 `desktop/output_listener.py` + `desktop/bridge.py`：C1 事件 → 界面（Qt 无关核心 + Qt 信号桥接）。
- M5 `desktop/stdio_fallback.py`：stdout/stderr 为 None 的兜底。
- M6 `test/desktop-client/`：启动→关闭、重复关闭、启动失败后清理、import 无副作用、stdout 为 None 时启动与输出不崩、三类事件渲染、错误事件映射。编排器用替身注入，无网络。

可选加固（O，客户未确认前不实施）：

- O1 输出区文本上限（几千行后截断），防止长项目撑爆内存；成本约 20 行。
- O2 「取消」按钮（除关窗外主动中止任务）；需编排层支持协作式中断，可能要新契约 → 大概率不属于本角色。
- O3 启动时把日志文件路径显示在状态栏，便于用户自查；成本小，但涉及界面信息设计。

## 6. 已知契约缺口（需交回调度）

C1 订阅是**实例级**，而管线里派发出去的子智能体是各自独立的实例。桌面端只能订阅注入给它的那一个对象，子智能体的事件（PRD/后端/前端的流式输出）**收不到**。C1 第 3 条也明确写了这一点。要让用户真看到完整流式输出，需要编排层提供「把监听器下发到子智能体」的公开入口——这属于新契约，本角色不得自己在界面层补判断。

## 7. 阻塞（本轮未实施的原因）

ShellGate（`pm` 规则集）拒绝 `python -m pip install PySide6`：要求固定版本、项目内虚拟环境、客户授权。本机无任何 Qt 绑定（`pip show PySide6` / `PyQt6` 均未安装）。没有 Qt 就无法验证窗口启动、信号跨线程投递与线程回收，按 workflow 规则不能给 `S4-DONE`。

解除方式（任选其一，需客户/PM 决策）：授权一次性安装（固定版本 + 项目内 venv）；或由「装配」角色在 S5 先把 `PySide6` 落到 `requirements.txt`，本角色再按清单安装。
